# 物件画像の入れ方

画像は **Supabase Storage** に保管し、DBには Storage 上のパスと表示順（`PropertyImage`）を持つ。
Vercel はサーバーレスでファイルシステムが永続しないため、実行環境やリポジトリには置けない。

画面に出すときは、サーバー側で会員限定物件の秘匿判定を通したうえで、
**都度発行の署名付きURL（既定1時間・`src/config/images.ts`）** を作って `<img src>` に渡す。
公開バケットにして直リンクで表示する方式はやめた（会員限定物件の写真が
URL 推測だけで未ログインに見えてしまうため。2026-08-28 の是正）。

## 事前準備（人間の作業・1回だけ）

1. Supabase → **Storage** → 新しいバケットを作る
   - 名前：`property-images`
   - **Public は無効（非公開）にする**（会員限定物件の画像を直リンクから守るため。
     公開のままだと管理画面の「保管先の接続確認」が警告を出す）
2. Supabase → Project Settings → **API** から次の2つを控える
   - Project URL（`https://xxxxxxxx.supabase.co`）
   - **service_role** キー
3. Vercel の環境変数に設定する

| キー | 値 |
| :--- | :--- |
| `SUPABASE_URL` | Project URL |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role キー |
| `SUPABASE_STORAGE_BUCKET` | `property-images`（既定値と同じなら省略可） |

> **`SUPABASE_SERVICE_ROLE_KEY` に `NEXT_PUBLIC_` を付けないこと。**
> このキーは行レベルセキュリティを無視してDBを全操作できる。`NEXT_PUBLIC_` を付けると
> ブラウザへ配信され、閲覧者の誰でもDBを読み書きできるようになる（S-01）。

設定が済むまで、管理画面のアップロードは押せない状態になり、その旨が表示される。

## 入れ方1：ファイル名で一括（初回投入・まとめ更新）

`/admin/properties` →「**画像を一括アップロード**」

ファイル名を「**物件管理番号_連番.拡張子**」にして、まとめて選ぶ。

```
6991580385_1.jpg   → 内山の物件の 1枚目
6991580385_2.jpg   → 内山の物件の 2枚目
6991837899_1.jpg   → 前山の物件の 1枚目
```

- 連番は省略できる（`6991580385.jpg` は1枚目になる）
- 区切りは `_` でも `-` でもよい。ゼロ埋め（`_02`）も可
- **同じ連番のファイルを入れると、その枚だけ差し替わる**（重複して増えない）
- 物件管理番号がDBに無いファイルは**取り込まず、理由を1件ずつ表示する**

## 入れ方2：物件ごとに個別（差し替え・追加）

`/admin/properties/[id]` の「物件画像」から追加する。
ファイル名は自由。既にある最大の並び順の次から自動で採番される。
各画像の左上に並び順、右上に削除ボタンが出る。

## 制限

`src/config/images.ts` の1箇所で決めている。変えるときはここを直す。

| 項目 | 値 |
| :--- | :--- |
| 形式 | jpg / jpeg / png / webp |
| 1枚あたり | 5MB |
| 1物件あたり | 20枚 |

Supabase の無料枠は1GB。1枚2MBで計算すると約500枚が目安になる。

## 表示

- 物件一覧のサムネイル：**並び順が最も小さい1枚**
- 物件詳細：メイン画像＋サムネイル（4枚まで）
- 画像が1枚も無い物件：既定のプレースホルダ画像が出る

**会員限定物件（`disclosureLevel=1`）は、未ログインには画像を返さない。**
価格・所在地と同じくサーバー側で落としている（S-07）。

## 注意

- 写真は物件の事実データとは別に、**撮影者・元付業者の著作物**にあたる。
  掲載許可の範囲に写真が含まれているかを確認すること。
- 画像を削除するとDBの行と保管先のファイルの両方が消える。**元に戻せない。**
  保管先の削除だけ失敗した場合は、DBからは消えてファイルが残る（表示はされない）。
